Handoff for build and release agents: a macOS build embeds the URL in `MAC_APP_URL`; that URL must return a JSON feed shaped exactly like `{"version":"0.2.0","url":"https://downloads.example.com/FM1-Grid-0.2.0.zip"}`. Build, sign, notarize and staple the `FM1 Grid.app` bundle first, then make the update zip with `ditto -c -k --sequesterRsrc --keepParent "FM1 Grid.app" FM1-Grid-0.2.0.zip`; that preserves the bundle root and signature metadata, and the zip must contain the `.app` at its top level (one nested directory is also accepted). The feed's `version` must equal the zip's `CFBundleShortVersionString` and be numerically newer than the installed app; the zip's `CFBundleIdentifier` must match the installed app, and a signed installed app accepts only an update signed by the same Team ID. Publish the zip and feed over HTTPS (the updater rejects relative and non-HTTP URLs), then build with `FM1_GRID_BUILD_VERSION=0.2.0 MAC_APP_URL=https://downloads.example.com/latest.json cargo build --release -p fm1-grid` so the displayed/fallback version and the feed URL match the release; republish the feed last so clients never see a version before its zip exists. No `MAC_APP_URL` means no macOS updates; the app stays on its current version, and the swap needs write access to the installed `.app` (a read-only or translocated bundle cannot update).
